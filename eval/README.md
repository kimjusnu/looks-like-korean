# eval/

이 폴더는 **데모 예문 세트**다. 저장소 README 첫 화면에 놓이는 별 끌 자산이라
공개 저장소이며, 예문은 전부 **이 저장소에서 직접 쓴 글**이다.

## 파일

| 파일 | 내용 |
|---|---|
| `examples.json` | 예문 9쌍. 사람이 실제로 겪을 법한 상황, 장르 6종 |

## provenance 정책 (이게 이 저장소의 4대 철칙 중 1번)

**자체 작성만 허용한다. 실전 데이터는 금지한다.**

- `before` 와 `after` 는 둘 다 **이 저장소에서 새로 쓴 한국어 원고**다.
- 실전 공모 제출물, 기관 공고문, 실제 일반인이 쓴 참여 의견에서 한 글자도
  인용·복제·의역하지 않는다. 사설 코퍼스를 읽고 예문으로 만드는 행위도 하지 않는다.
- `meta.provenance` 는 `"self-authored"` 로 고정한다.
- `after` 에 `before` 에 없는 사실을 새로 넣지 않는다. 새로 들어간 사실이 있으면
  그것은 사람이 쓴 증거가 아니라 **다른 글을 쓴 증거**가 된다.

## 쌍의 계약

한 쌍(`before` / `after`)은 아래를 모두 만족해야 한다.

1. **사실 불변** — `kept_facts` 에 적힌 수치·고유명사·조건이 **양쪽 원고에 실제로 들어 있다.**
   적힌 항목은 문자 그대로 두 원고에서 찾을 수 있어야 한다(의역이 아니라 리터럴).
2. **레지스터 단일화 완화** — `after` 의 `uniformity_index` 가 `before` 보다 **낮다.**
   `before` 는 레지스터 한 종류로 끝나야 하고(1.000), `after` 는 2종 이상 교차해야 한다.
3. **`before` 는 그럴듯한 AI 글** — 형편없는 AI 글은 예시로 쓰지 않는다. 관용구·번역투·
   균일한 종결이 자연스럽게 묻어나와야 「아, 이런 거구나」 하고 납득된다.
4. **`after` 는 기계 치환 티가 없어야 한다** — `~습니다` → `~해요` 일괄 치환 금지.
   리듬이 살아 있고 결함만 있는 문장으로 골라야 한다.
5. **영문 금지** — `before` 에 영문 문장을 넣지 않는다. 이 저장소의 이름과 목적이 그것이다.
6. **문장 수 4~10** — `before` 와 `after` 각각.

## 새 예문 추가하는 법

1. `examples.json` 에 항목 하나를 추가한다. `id` 는 `ex-NN` 순번.
2. 장르를 겹치지 않게 고른다(리포트·제안서·자기소개·메모·블로그·긴글).
3. `before` 를 쓴다. **레지스터 한 종류로 끝나게** 쓴다. 억지로 일부러 맞추지 말고
   AI에게 그 장르를 쓰게 했을 때 나오는 그대로 쓴다.
4. 사람이 실제로 고칠 길을 따라 `after` 를 쓴다. **어미를 교차시킨다.**
5. `kept_facts` 에 **두 원고에 공통으로 들어가는** 사실만 적는다.
6. `why` 에 무엇을 왜 고쳤는지 적는다. 한국어 리듬 차이로 설명한다.

## 검증

`examples.json` 을 눈으로 믿지 마라. 계측기를 돌린다.

```bash
cd <저장소 루트>
set PYTHONPATH=src
python -c "import json,io,sys; from looks_like_korean.metrics import analyze; d=json.load(io.open('eval/examples.json',encoding='utf-8')); [print(e['id'], round(analyze(e['before']).uniformity_index,3), round(analyze(e['after']).uniformity_index,3)) for e in d['examples']]"
```

`after` 의 값이 `before` 보다 **높거나 같으면 통과한 게 아니다.** 어떤 쌍이 그러면
원인을 분석해 그 쌍을 고친 뒤 다시 돌린다.

추가로 확인할 것:

- `kept_facts` 의 각 항목이 `before` 와 `after` 양쪽에 리터럴로 들어 있는가
- `register_mix_before` / `register_mix_after` 선언이 실제 분류기 출력과 같은가
  (다르면 `analyze()` 의 `register_counts` 에서 실제로 나온 값을 그대로 쓴다)
- `before` 에 영문자 2자 이상이 연속으로 나오지 않는가
- 문장 수가 각각 4~10인가

## 방향 표에 대한 주의

`metrics.py` 의 방향표는 **가설**이다. 같은 날 실측에서 9개 지표 중 7개가 역전되었으며
(`metrics.py` 모듈 docstring 참고), 코퍼스가 장르 대칭이 아니므로 그 실측을
**반증으로 읽어서는 안 된다.** 그래서 이 예문 세트가 하는 일은 좁다 —
「기계 글은 어미가 단일하다」는 **직관**이 지표에 어떻게 투영되는지 보여주는 것이고,
가설을 검증한 것이 아니다.
